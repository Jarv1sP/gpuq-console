# 架构与信任边界

本页描述当前源码支持的接口与保护边界，不表示每个部署都已启用对应能力；节点开关、常驻服务版本和实际验收范围须分别核实。

## 两种身份，不要混淆

- **平台身份**：独立用户名/密码、`member` 或 `admin`、逐机额度与总额度。注册建立的是用户账号，不是设备记录；不创建用户电脑的 Tail 身份或服务器系统登录账号。密码独立盐 PBKDF2，登录 token 不明文落数据库，Cookie 只允许同源 HTTPS。
- **管理网络身份**：VPS 和 GPU 节点加入 Tail，使用 OpenSSH。用户电脑通过 HTTPS 连接门户，无需加入 Tail，也不会在注册、登录或安装 CLI 时自动登记到 Tail。Tail 权限不会自动变成门户管理员，门户审批也不反向授予 Tail/OpenSSH 权限。

正式门户由 `login-sessions.mjs` 管理登录：SQLite 仅保存 token 的 SHA256 与账号/角色/到期时间，正常使用按小时延长 30 天闲置期限，不保存密码或原始 token。浏览器一年期 HttpOnly/Secure/SameSite Cookie 只是凭据缓存，授权仍受服务器期限、停用和角色检查约束。普通查询不写 Cookie，保持已有账号切换竞态隔离；CLI 的 0600 缓存无需重写。退出、账号撤销与到期清理直接删除数据库会话，服务重启不会复活。示例服务仍使用原内存会话。

已有 Tail + OpenSSH 直连属于独立管理入口，继续服从原有 ACL、系统账号和 SSH 密钥。`gpuctl ssh` 是门户授权的 HTTPS PTY，默认进入个人工作区，不能当作原生 SSH 端口使用。基础设施访问与普通用户训练无需使用同一种身份或入口。

Portal 在容器 UID 1000 下运行，只读程序，保存 SQLite。宿主机执行桥通过只读挂入容器的 Unix socket 接收固定操作，再以专用密钥调用节点强制命令。SSH 私钥不挂入网页容器。只读采集另用一把密钥，主机指纹必须预先校验。

门户控制面只通过 Caddy 的 HTTPS/证书端口公开；可另行配置短期票据保护的专用 HTTPS 上传入口，不开放通用节点访问。不要发布执行桥、数据库、采集目录或节点 GPUQ socket。配置 HTTP 反向代理时必须覆盖 `X-Real-IP`，防止客户端伪造限流来源。

普通注册码只创建零额度成员，不授予管理员。注册码同时保存核验摘要与 AES-256-GCM 密文，独立密钥文件随私有备份保存；只有管理员专用接口可读取当前有效码，普通状态接口不包含明文。轮换立即作废旧码，不改变已注册账号。删除账号需先暂停、没有未完成任务，且不能删除当前自己或最后一名可登录管理员。

## 页面职责与可见信息

- **我的工作台**：手选服务器上的个人项目、开发终端、文件、训练版本/产物和额度；管理员也不在这里混看所有人的任务。
- **机器资源**：机器与逐卡健康/占用信息，包括 GPU 利用率、显存、温度、功耗、CUDA 计算进程（不含图形进程）。管理员可查看 PID、程序名、系统用户与占用显存，并展开原 GPUQ 队列，最多本次采集的最近 100 条。普通账号只能查看获授权机器的指标、进程 PID 和占用显存；后端移除程序名、系统用户名和原 GPUQ 队列，不把他人的命令或路径发给客户端后再用界面隐藏。
- **用户授权**：管理员专用的账号审批、角色、注册码、逐机和总卡数授权；管理 API 独立做角色校验。
- **帮助**：一个“使用指南”入口，按首次使用、开发、训练、数据、结果、排队与故障分章阅读。网页仅提供普通使用说明；管理员运维手册保留在仓库，不公开提供 `/guide/admin` 或原始 Markdown 路由。

节点只读采集约每分钟执行一次，页面每 15 秒读取最近快照。逐卡监控不是强实时锁或可用配额证明。界面区分采集时间、过期/不可达、缺失指标和真实零占用；计算进程查询失败或不完整不能当作没有进程。未授权用户不接收对应节点的快照。实际授权由门户策略决定，作业执行仍由 GPUQ 队列决定。

操作系统计算进程与 GPUQ 队列是两种视角：GPUQ 队列可包含等待中或旧入口提交的作业，操作系统也可能运行队列之外的可信管理员作业。原队列只读展示不代表普通用户获得旧 GPUQ 的直接控制权。

人类可读的任务信息由门户记录提供：账号 `name` 是自填姓名／显示名，任务保存 `submitterName` 快照和自填 `description`，不写入原节点 job spec。`task-catalog.mjs` 按机器和精确 `nodeJobId` 生成只读白名单；状态接口、逐卡进程、队列及 CLI 共用这份目录，不解析 `portal-` 前缀或用卡号猜用户。同机器授权成员可见姓名、任务名、描述及状态，但不可见他人命令、路径、日志或结果。原始进程所属 GPUQ 任务仍由节点 cgroup 采集确认；没有证明就不关联。旧任务缺少描述显示未填写，缺少姓名快照按不可变用户 ID 查现有姓名，不按可复用用户名关联。

## 调度与额度

默认提交仍须明确获授权的服务器；缺失机器且未明确自动选机、未知机器均拒绝。已发布的 OCI 项目可显式使用 `machine:"auto"` 或 `machineSelection:{mode:"auto"}`，后端按授权、健康、维护、资源/调度能力、项目架构与可信复制通道、数据使用权筛选候选，并持久化唯一目标。优先可用余量与空闲卡，再参考队列及项目/数据就绪情况；这是提交时快照，不保证准备后仍空闲。目标固定后不因忙碌、超时或重启改派。GPUQ 仍只在选定节点内分配 GPU，不将多机显卡拼成一个作业。

先核验固定项目版本。自动选机的项目复制与显式数据准备可进入持久 `PREPARING_DATA`，此阶段不占 GPU 额度；项目及本机数据重新核验 READY 后，原子检查当前授权与单机/跨机配额，再保存额度预留并请求 GPUQ。数据传输和远程读取不持有全局修改队列。`QUEUED`、`STARTING`、`RUNNING`、`UNKNOWN` 等已经预留的非终态保留额度；节点确认终止后才释放。网络失败不能被当成任务成功停止。

节点提交键绑定不可变用户 ID、任务 ID；中文名字在 GPUQ 的 ASCII owner 标签里映射为稳定 ID 摘要，不作为权限依据。原 GPUQ 任务继续由同一队列执行，新门户不清库、不搬旧作业、不抢占已有实验。

当前启用的管理员可以访问清单内全部机器，共享与独占任务均免个人累计用卡额度；成员仍同时受逐机与合计额度约束。管理员单任务不能超过选定机器的物理卡数，也不能绕过节点准入、显存预算、数据权限或物理资源竞争。管理员通过 `gpuctl run` 在资源不足时正常排队，不因身份强行停止他人训练；原始 root 命令不受队列保护。首次派发重新检查当前角色与授权，降级后未派发任务不继承豁免；已尝试派发或结果未知的任务按原身份和提交键保守对账，不自动停训或释放资源。

## 工作区与设备

普通账号没有独立宿主机登录密码。旧工作区及 venv 项目使用节点服务用户的 bubblewrap 沙箱：只读系统/基础 Python、独立进程/网络空间，训练挂载分配的 GPU，普通终端不挂 GPU。已显式启用的 OCI 项目使用 rootless 容器，容器内 root 不是宿主机 root，不暴露宿主引擎 socket、宿主网络或任意 GPU。路径操作拒绝越界和软链接穿越。未带项目字段的旧任务仍使用原个人持久 `/workspace`，不自动搬迁。

新项目按用户 ID、机器、slug 隔离开发代码、环境、HOME 和 scratch。`shared` / `isolated` 项目开发终端可写 `/workspace` 与 `/opt/project-env`；基础 `/opt/conda` 只读，私人 venv 分别继承或不继承基础包。`oci` 项目使用镜像自己的 Python/系统包，不挂载宿主 Conda 或项目 venv；三种模式在创建时选定，旧项目不自动转换。训练固定发布版本，代码只读，拥有独立 HOME 与 `/outputs`；程序应将结果写到 `/outputs`。命令只在隔离环境中执行，发布不在宿主机运行上传代码或包安装钩子。

发布前必须关闭开发终端并确认整个 systemd 进程组已停止；控制面失联或停止状态不明不视为成功。未完成上传阻断发布。项目上传先写服务私有 staging，校验最终大小及 SHA256 后原子替换草稿；发布按项目加锁，完成复制、二次校验与元数据一致性检查后一次 rename 暴露完整版本。OCI 发布还将停止态开发容器提交为固定镜像 ID，与代码快照共同绑定 release。项目模式训练提交显式携带 project+release，并在预留显卡前校验 READY，节点使用时再验证。输出读取只核原任务与归属，不因基础环境后续升级而重新要求旧版本能运行。

venv 发布冻结本机代码与私人 venv，不包含全部基础软件；基础指纹只覆盖解释器与包元数据，无法证明所有系统库 bit-for-bit 不变。OCI 发布则固定代码与镜像，支持在已授权且兼容的节点间经受信 TLS 复制，手动复制或 AUTO 准备均沿用持久操作编号，不覆盖不兼容的目标项目。复制不迁移运行容器、开发草稿/HOME 或训练结果，也不等于自动归档或独立备份；基础环境/驱动维护仍须验证。接口及路径详见 [项目手册](PROJECTS.md)。

训练默认每卡 4 核 CPU 额度、32 GiB 系统内存；普通终端 2 核、8 GiB。NCCL 设置共享内存兼容项用于同机多卡。这些系统资源约束不是跨机 DDP 自动编排；共享 GPU 的显存准入与可选 HAMi 能力另行检查。

这不是不可信租户的虚拟机级防护。Linux 内核、驱动和命名空间有共同攻击面；服务用户、VPS root、门户管理员（启用 host-root 时）均属高信任主体。**不应把此系统卖作恶意公网租户的强隔离 GPU 云。**

## 数据集状态与准备边界

数据仓库目录元数据可由所有启用的登录成员浏览，读取内容仍按机器和不可变平台用户 ID 授权。`datasets.catalog` 的版本与副本分别带 `canUse`，他人 READY 不代表本人可用；零额度成员可以看目录但不能创建终端、上传或训练。客户端只提交名称与完整内容版本，管理员批准的来源编号与宿主机路径留在节点可信配置中。网页按钮、门户授权、节点所有者验证和执行时 `READY` 校验分别承担职责，不能以隐藏按钮代替后端权限。

数据版本以文件清单与 SHA256 固定：`REGISTERED` 表示已登记，`STAGING` 表示未发布内容，只有本机同文件系统的无覆盖原子发布后才为 `READY`。后台任务另外使用 `REGISTERING`、`PREPARING`、`FAILED`；`STAGING` 不证明后台仍在运行。准备阶段不申请 GPU，失败、失联、锁忙或未知状态不得按就绪处理。提交检查发生在额度预留前，节点仍在使用前检查授权与本地就绪并取得持久租约。

新缓存默认位于 `/data2/datasets`；数据根必须是核实过的本地非系统盘挂载，运行时继续检查，不能在挂载丢失后回落写系统盘。旧 TB 数据只按明确范围原位登记，不自动搬移或全盘扫描；登记本身需要计算范围内内容哈希。统一目录展示全节点固定版本的元数据，不公开他人的文件清单、个人目录或内容；操作仍使用本人授权。按需跨机准备复用持久传输服务、固定私网 TLS peer 和证书 pin，无第二套复制调度器；逻辑名称映射到目标个人副本，实际内容版本和本机 READY 必须匹配。原有批准的 LAN/NFS 来源仍兼容，不因升级新增挂载或迁移旧数据。训练只读挂载本地 `ready/NAME/VERSION/data` 到 `/data2/NAME`，不暴露宿主机整个数据盘。

租约是独立于 GPU 额度的持久删除保护，不按时间自动失效。只有可信执行层确认作业及其子进程结束才可释放；管理员清理副本也不能绕过活跃租约。文件 mode 只读不保护数据免受可信服务账号/root 修改，训练只读隔离由执行器挂载落实。目录准备、数据传输、GPU 调度与个人环境分别验收，不相互替代。

分层存储支持可选的 HDD 原件归档与水位驱动缓存回收，两者分别默认关闭。只有固定权威原件完成校验和保护、本机获得有效恢复回执后，副本才可转为 `cache`；GC 再核当前来源、无租约/固定标记和无未知状态，保留登记及恢复路径。唯一原件、未认证旧数据、工作区与结果不进入这项回收。可选 timer 不会随安装自动启用，HDD 原件也不等于独立备份。配置与流程见 [数据集手册](DATASETS.md#hdd-长期版本与本地热缓存)。

`deploy/slurm_backend.py` 当前是经测试的适配基础，并未接入生产执行链；现有项目发布、OCI 跨机复制、数据集接口或只读来源可用不代表 Slurm/Pyxis/Enroot 已上线。后续调度迁移仍须逐节点排空，禁止旧 GPUQ 与 Slurm 同时管理同一组卡。

## 明确的限制

- root 终端是真宿主机 root，需节点显式启用；账号角色变更撤销登录，但不能撤回已经执行的命令。
- 审计记录授权/任务/终端操作，不是所有 shell 命令的不可篡改录屏。
- 内核硬磁盘配额须单独配置和验收；未启用时，上传预留空间检查不能限制训练自行写满磁盘。
- 用户项目代码/结果、个人数据空间文件和终端仍可经 VPS HTTPS；数据集上传另支持票据保护的节点直传，能力与实际通道须分别确认。CLI `ssh` 不是 SSH 协议。
- 项目/结果不参加数据集缓存 GC，训练结果不自动归档；独立内容备份须另行配置验收，门户数据库备份不包含代码、环境、数据和模型。
- 门户/CLI 已有按节点能力放行的弹性、显式抢占与共享/HAMi 接口，不是管理员原生命令的别名。共享仅单卡、明确显存预算、普通排队且不自动让位/恢复，不与弹性混用；HAMi 显存能力不证明 SM 限流可用。独占保存让位须程序适配 checkpoint，P3/P4 仍仅管理员可选。详见 [调度约定](SCHEDULING.md) 与 [训练控制](TRAINING_CONTROL.md)。
- `UNKNOWN`、过期状态失败关闭；没有“自动清零所有占卡”的危险恢复动作。

漏洞报告见 [SECURITY.md](../SECURITY.md)。
