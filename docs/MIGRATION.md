# 名称更新与兼容

项目名称统一为 **GPUQ Console**，仓库为 [Jarv1sP/gpuq-console](https://github.com/Jarv1sP/gpuq-console)，新客户端命令为 `gpuctl`。平台面向满足部署条件的 NVIDIA GPU Linux 服务器，不依赖服务器厂商。

## 普通用户

- 不用重新注册、重新申请额度或搬运项目。账号、授权、任务和个人工作区继续沿用。
- 新安装使用网站的 `install.sh`，安装后执行 `gpuctl login`、`gpuctl use gpu-1` 等命令，参数和工作流程不变。
- 已安装的旧 `amax` 命令仍可继续访问兼容接口；不必为了改名中断工作。建议下次客户端升级后使用 `gpuctl`。
- 新 CLI 兼容旧登录缓存和旧环境变量。显式指定的会话文件、网站地址仍优先使用；不要公开缓存文件，其中含登录凭据。
- 注册码不会因名称更新失效。管理员主动刷新才生成 `GPUQ-` 前缀的新码，同时作废上一个码；已注册账号不受影响。

## 已有部署

**改项目名不等于迁移生产基础设施。** 以下内容不自动改动：

- 门户域名、DNS、TLS 证书和反向代理入口。
- 机器 ID、Tail 节点名称、SSH 用户及授权密钥。
- 数据库、邀请码密钥、GPUQ 状态、个人工作区与训练文件路径。
- 容器名、系统服务名、执行 socket、节点桥安装位置和 root 入口。
- 已排队或正在运行的训练任务。

全新部署文档使用 `/opt/gpuq-console`、`gpuq-console-*.service`、`gpuops` 和 `/srv/gpu-workspaces`。它们是新部署示例，不是要求旧部署照抄执行的迁移命令。旧安装若仍有历史名称，应保留实际配置；尤其不要直接在运行目录套用全新 Compose 或节点安装器，否则可能另建容器、指向空数据库或使执行桥断开。

升级时先备份，比较新旧配置，只替换经验证的软件文件并保留现有部署参数。不要为了外观一致修改机器 ID、移动任务数据或重启 GPUQ。确实需要迁移基础设施名称时，另定维护窗口，按[部署手册](DEPLOYMENT.md)逐项验收和准备回退。

若另外使用 GPUQ 的高级 fleet / sync 工具，升级前检查其独立清单：每个 `hosts` 条目须显式填写目标机器上 `binary`、`config` 的绝对路径。原来已正确填写的无需修改；不再依赖历史硬编码默认值。这不是门户的 `inventory.nodes`，不会自动迁移现有 GPUQ，示例见 [GPUQ 手册](../gpuq/README.md#高级-fleet--sync-的独立配置)。

## 贡献者

克隆新仓库地址；已有 Git 工作目录可只更新 remote URL：

```sh
git remote set-url origin https://github.com/Jarv1sP/gpuq-console.git
```

这不会改本地目录、历史提交或生产服务。新增界面、示例、文档和命令统一使用新名称；为兼容旧客户端保留的标识不能机械删除，应有回归测试后再调整。
