# 独立终端会话与重连

每次 `gpuctl ssh`（包括 `--root`）和网页“新建独立终端”都创建独立 PTY。同一个账号的多个客户端不会共享终端；在一个会话输入 `exit` 只结束该会话。ROOT 仍只对既有管理员、已授权且启用 hostRoot 的节点开放，不因本次升级扩大权限。

终端输出会显示完整会话 ID。`Ctrl+]` 或网页“断开”只释放当前写入权，保留终端和其已有命令。显式重连：

```sh
gpuctl ssh gpu-1 --reconnect SESSION_UUID
gpuctl ssh gpu-1 --root --reconnect SESSION_UUID
gpuctl ssh gpu-1 --project vision --reconnect SESSION_UUID
```

服务器、项目和 ROOT 模式必须与原会话一致。CLI 不把写入凭据保存到多个代理共用的账号缓存中。网页按账号、服务器和项目保存开发终端 ID，刷新后作为重连输入的默认值，并在总控保留“重连”入口。存储只包含身份和 ID，不保存输入、输出或写入凭据；ROOT 和个人数据终端不写入这份项目记录。

CLI 在打开请求发出前打印原 UUID、范围和只读 status 命令，并把这些恢复资料按账号保存在本地登录缓存。503、丢回执或身份／租约不匹配时，错误 JSON 保留 `terminal.state=UNKNOWN` 与原查询命令，不会换编号或进入交互；只有原 ID、连接身份和未过期写租约全部匹配后才接受输入。

刷新后选择原项目会用 `terminal.status` 只读核验已保存的 ID，不自动重连、接管或结束。未知、查询失败仍保留原 ID；只有“结束终端”明确确认后才移除记录，项目发布前沿用原来的全部开发终端结束流程。禁用浏览器存储时请复制会话 ID 后再刷新。

## 单写租约

一个会话同时只接受一个客户端写入。每个附件都有独立客户端 ID 和服务器写入凭据；正常轮询续约，停止轮询 30 秒后写入权过期。过期不终止 PTY，但旧凭据不能继续输入、调整窗口或结束会话，须显式重连。

其他客户端仍在线时，普通重连被拒绝。如确实要接管，必须主动指定：

```sh
gpuctl ssh gpu-1 --root --reconnect SESSION_UUID --takeover
```

网页会要求单独确认。接管会更换写入凭据，旧客户端不能继续写入或关闭终端。已经被服务器接受或开始执行的命令不会因接管撤销。同一个会话 ID 和写入凭据也不能绕过账号、项目、服务器或 ROOT 权限边界。

网络中断后不自动创建替代会话、不自动结束旧会话；保存会话 ID，等待租约过期或明确接管再重连。创建/重连请求的 UUID 连接键用于同请求重试，不能用同一个新建键创建另一个终端。

## 原会话不可达时

不必先重连才能查状态。保持原服务器、项目与终端类型：

```sh
gpuctl terminal status SESSION_UUID --machine gpu-1 --project vision
gpuctl terminal close SESSION_UUID --machine gpu-1 --project vision
```

ROOT 原会话改用 `--root`，个人数据终端改用 `--data-workspace`；未指定项目时沿用该机器已选项目，旧个人工作区用 `--legacy`。两条命令均不需要交互式 TTY。

`status` 不附着、不输入、不续租，返回 `ALIVE / STOPPED / UNKNOWN`。`STOPPED` 需要原会话单位、PID、cgroup 和缺失 socket 的一致停止证据，网络错误不是停止证据。它不提供已丢失的历史输出或退出原因。

这里的 `terminal close` 只收口已证实停止且写入租约失效的本人会话记录；不会停止存活或未知终端，也不会取得写入权。正常在线终端仍通过 `exit` 或网页“结束终端”使用当前写入凭据结束。原 ID 的归属记录和项目安全围栏保留，不能重新用这个 ID 新建 PTY。收口响应不确定时查询同一 ID，不自动新建或重放输入。

网页在确认原会话停止后明确提示“已结束，请新建独立终端”，不会假装恢复旧终端。上述状态协议需要门户、执行桥和节点配套升级；旧节点拒绝时不会降级为无凭据停止。

## 升级与项目发布

旧终端进程不会因升级自动重启或关闭。旧客户端没有单写凭据，升级后其输入/关闭请求会明确拒绝；请更新 CLI 或刷新网页。旧会话首次接入新协议必须指定会话 ID 并明确确认接管。未知、不可达或已结束的会话不会被默默替换，须核实后另行新建。

项目发布检查该用户、该项目的全部新会话以及旧会话指针。只结束其中一个不足以解除发布阻挡；所有开发终端和其子进程均确认结束后才能发布。普通断开、租约过期都不等于结束开发终端。

现有 PTY 生命周期仍为无输入 1 小时或累计 6 小时自动结束，单写租约不延长该期限。以上描述是协议行为；只有部署并验收对应节点后才代表生产可用。

## 执行桥升级：保留终端加速配置

终端加速使用常驻的受限 SSH 通道，只优化传输，不重建 PTY、共享终端或放宽权限。门户和节点仍逐次核对账号、会话和写入租约。

`deploy/execution-worker.py` 中的 `TERMINAL_STREAM_HOSTS` 是按机器 ID 显式开启的部署配置，仓库模板默认为空，以兼容尚未升级的节点。例如，仅在两个节点的流协议入口已部署并验收后：

```python
TERMINAL_STREAM_HOSTS = ('gpu-1', 'gpu-2')
```

重新生成或替换整份执行桥时，必须备份并保留已验收的开关列表，核对各 ID 属于当前部署清单且节点支持匹配的 `terminal-exchange-stream-v1` 入口，再审查生成文件差异。不要直接用模板的空列表覆盖生产配置，也不要对未升级或未验收的节点开启。空列表仍可使用原 RPC 传输，但不会保留已部署的交互加速；单纯重启服务不会把模板配置自动合并到已有文件。

升级后，用自己的新旧会话分别检查输入、回显、断开和结束；已有 PTY 无须重建。通道轮换不重发已发送的输入，连接或输入结果不确定时不自动重试命令。
