# GPUQ 控制进程发布门禁

`native-release-gate-v1` 是控制进程滚动升级的观察屏障，不是用户维护开关，也不替代机器授权、租约或业务作业隔离。它不修改数据库结构或任务规格。

## 固定合同

调度器只读取 `/run/gpuq-native-release/gate.json`。目录必须由 root 所有、权限 `0755`；文件必须由 root 所有、权限 `0644`、普通单链接文件，最多 4096 字节。读取使用 `NOFOLLOW`、固定目录文件描述符，并核对读取前后的 inode、大小和时间身份。路径、开关不能由环境变量、普通 RPC 或数据库设置覆盖。

文件只有以下五个字段：

```json
{"schema":1,"state":"CLOSED","releaseId":"22222222-2222-4222-8222-222222222222","bootId":"当前主机 boot ID","deadlineMonotonic":12345.0}
```

`releaseId` 为规范 UUID；截止时间使用当前启动周期的单调时钟，必须在未来且不超过 600 秒。合法文件表示关闭；非法字段、重复键、错误 boot ID、软硬链接、身份变化、读取失败或截止时间过期仍保持关闭。**到期不会自动放行。** 文件不存在时保持已有调度行为；只有受保护发布器显式移除原文件才恢复。

## 关闭期间

- `health/status/show/job_watch/events/log_path` 保持只读。提交、取消、重试、优先级、展示标签、observe 模式、同步和 fleet 写操作均拒绝，不能通过设置 `observe_only=false` 解锁。
- tick 仍读取物理 GPU、原 systemd unit 身份，完整核对 UUID/卡号、租约、预留及控制组；两次真实扫描后可报告观察健康。缺失单位、旧启动周期、租约异常或采集失败仍报告不明／降级，不推测空闲。
- 不写入进度、心跳或任何任务／动作／租约状态，不修复或重派旧动作，不执行启动、信号、清理和 checkpoint 请求。计划、恢复和实际动作入口也重新核对门禁。
- 观察健康不等于可调度；门禁关闭时可调度卡列表为空。`native_release_gate` 返回门禁状态、有效性和发布 UUID，供发布器核对。

## 发布边界

旧调度器不识别此门禁。发布器必须先暂停新准入并自然排空请求，只停止 GPUQ **控制服务**，持有既有发布互斥及 daemon lock 后重新检查真实动作、attempt、租约和任务单位；未知或变化即停止发布。不能仅写这个文件便假定旧进程已停止动作，也不能让文件检查替代对正在执行动作的排空证明。

门禁在控制进程已停止时建立；新控制进程恢复后先在关闭状态完成两次物理观察，核对原训练 PID、start ticks、InvocationID、attempt 和完整租约未变，然后才显式移除同一门禁并恢复原准入。移除会打断扫描连续性，正常调度需重新完成两次观察。任何不明结果保留关闭状态，不能回滚当前数据库或杀训练来获得“干净”窗口。

该源码能力不表示某个集群已启用或经过滚动升级实测。受保护发布器、真实 unit 依赖、现有私有版本与回退边界仍需另行审查；没有门禁能力的旧进程不得冒充满足此合同。
