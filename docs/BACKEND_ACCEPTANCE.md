## 已完成的真实验收

| 项目 | 实测结果 | 范围与限制 |
| --- | --- | --- |
| 八卡 Ray | 一台八卡 RTX 5090 上，8 个独立 actor 完成 CUDA 运算；Ray 按作业预算识别 32 CPU、256 GiB 内存，GPU UUID 与分配一致。PID 峰值 539，OOM／PID 配额事件为 0，退出后释放资源。 | 不代表任意 Ray／训练框架、全部机型或长期满载均已验证。 |
| 四节点个人工作流 | 四台节点的小样本覆盖独立终端、个人数据发布、固定代码版本、单张真实 GPU 计算、结果哈希、诊断及 GPU／数据租约释放。 | 使用管理员的个人工作区，不冒充普通角色在所有节点的完整验收。 |
| 普通成员校内直传 | 注册后的零额度拒绝、单机授权、4 MiB 原始文件直传、明确收到 1 MiB ACK 后重新连接续传及完整 SHA256 核验通过。 | 校园物理入口传文件，VPS 只管理授权；不代表任意校外网络、大文件吞吐或未知写入结果可安全重试。 |
| CD2 云端副本 | 普通成员的节点个人文件完成 4 MiB 上传、云端核验、下载及独立全文 SHA256 对账；业务经独立回执对账，并发发布中断的整轮失败记录保留，验收账号正常退出并暂停。 | 这是节点与云盘之间的文件流，不是浏览器直接上传云盘。独立云端冷读、几十 GB 吞吐与可靠备份仍未验收。 |
| 终端连续按键 | 同一台节点的公开 API 单字节按键响应为 118–155 ms；此前相同入口约 400 ms。双客户端独立会话、拒绝隐式接管、错误写入者不能关闭、关闭 A 后 B 仍可输入均通过。 | 是有限样本的 API 延迟，不是所有网络条件下的保证。首次打开／关闭另有初始化开销。 |
| 多客户端登录响应 | 真实 HTTP 回归验证：旧会话提示的 GET／HEAD 响应或旧 API 的 401 延迟到达，均不会删除另一客户端刚登录的 Cookie。正式服务的失效会话提示仍为未登录，受保护 API 仍返回 401，自己的有效会话仍通过鉴权；这些失败响应不发送删除 Cookie 的头。 | 两个 HTTP 客户端共享 Cookie 的定向回归，不代表所有浏览器组合均已验收。显式退出仍清除会话；未通过放宽鉴权或权限来修复。 |

终端优化只更换 VPS 执行桥，保留固定目标、主机指纹、密钥和强制命令；SSH 通道短期复用、限制并发，连接或输入结果不确定时不自动重发。现有训练、节点调度器、网络及前端未因这次桥更新重启。

登录响应修复已通过四项 Linux／Windows CI 并上线。仅更换门户服务的一个后端文件，其他 100 个镜像清单文件逐字保留；数据库、现有界面、执行桥和节点训练服务未被替换或恢复旧备份。发布时短暂暂停新操作，门户自然退出后启动新镜像，健康核验通过后解除自己的维护状态。原发布检查的拒绝与后续恢复分别保留，不把失败记录改写成成功。

## 当前部署边界

- 一台 RTX 3090 存储／验收节点已安装匹配的 34 模块运行时，并补充原取消任务的正常收敛修复；忙碌节点仅定向修补必要的互传叶文件，其余运行时保留兼容的 32 模块版本，尚未完成本轮整组滚动部署。不能把仓库最新代码、单文件热修或采集健康当成四机同版本。
- 云文件仅在单个存储节点启用。成员看不到后台云盘账号、令牌或其他人的文件；旧任务不自动重放。
- 四台生产节点的个人 OCI 和内核硬磁盘配额仍关闭。独立灰度的配额超限／恢复及私有管理器已经验证，但真实容器／GPU 全链路尚未通过，不承诺已提供容器内 root／apt 或个人硬磁盘上限。
- 网页的本机目录上传、个人数据空间文件上传仍经过 VPS；超过 256 MiB 必须明确同意中转。这个确认不会开启直传。`gpuctl data upload` 可选择已授权的校内直传；`gpuctl data put` 当前仍是中转。云端副本只处理已经在节点上的文件，不能把整个电脑到云盘流程称为绕过 VPS。
- 原训练继续运行，未为升级强停忙碌节点。已取消的历史任务不自动恢复；历史失败记录也不改写成成功。

后续扩大启用范围须分别验收节点运行时、浏览器直传的可信 HTTPS／受限 CORS、真实 OCI／GPU／超限行为及大文件性能。未通过的能力保持关闭，不用延长超时、重新提交或修改界面标签代替业务验收。
