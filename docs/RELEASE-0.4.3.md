# 0.4.3 — 可选的原件归档与训练缓存生命周期

本页描述候选版本能力与启用条件，不作为生产部署或真实业务验收回执。归档和 GC 分别默认关闭，须逐步配置和验收。

- 启用后，新单 owner 上传/发布产生持久归档事件：后台经固定 LAN 保存 HDD 原件，签发服务端私有授权，再认证目标缓存。旧数据默认保护，不批量扫描、搬迁或追溯归档。
- 用户仍选择上传/训练机器；读取自己的 HDD 归档不与权威机器 GPU 额度耦合。数据 owner、固定版本和授权继续校验，普通请求不能指定来源路径、端点、角色或证明。
- 归档状态独立于本机 READY。失败保留本地原件；网页或 `gpuctl data archive-retry NAME@VERSION --machine MACHINE` 明确重试原意图，未知状态不新建替代任务，永久取消须管理员处理。
- 准备后的持久 hold 交接到训练租约；新版下载持有覆盖整次读取的租约。停止事实不明时持续保护，不按 TTL 过期。旧 `sync data` 对启用 GC 的 cache 版本仍拒绝，受保护原件与 GC 关闭场景保持兼容。
- 经认证的 NVMe 缓存仅按明确预算及 80%/70% 水位回收，归档成功不立即删除。来源不可验证、存在 pin/租约或未知状态时拒绝回收；可选小时 timer 不随安装自动启用，HDD 原件节点不启用回收。

部署需要完整 27 模块节点运行时、配套门户和 12 个内部执行桥操作，先功能关闭发布，再验收新小样本的上传、归档、保护、驱逐、恢复与下载，最后独立开启 NVMe GC。程序切换须保留运行训练、账户、配额、原数据根和历史数据库；不以数据库回滚代替代码恢复。

HDD 唯一长期原件不是备份。本版本不迁移旧数据根、不归档训练结果/checkpoint、不实现独立备份，也不承诺未完成实测的业务已上线。
