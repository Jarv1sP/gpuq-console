# 项目网络与代理

项目终端、训练作业有独立的网络命名空间。宿主机能下载，不代表作业使用了同样的代理、DNS或缓存；作业里的 `127.0.0.1` 指向作业自身，不是宿主代理。

在项目终端中执行：

```sh
gpuq-network show
gpuq-network check https://pypi.org/simple/
gpuq-network check https://pypi.org/simple/ --proxy http://PROXY_HOST:PORT
```

第一条不联网，只显示代理是否设置（隐藏地址与凭据）。后两条由你明确指定目标，最多15秒，区分DNS和TLS/HTTP结果，不下载正文、不会跳过证书验证。HTTP 403/404等表示服务器可达但业务未成功，不等于下载成功。工具不默认探测任何AI服务。

一次安装使用代理：

```sh
gpuq-network exec --proxy http://PROXY_HOST:PORT -- python -m pip install PACKAGE
```

只影响这条命令及其子进程，不改宿主网络、不修改其他用户、不写入项目发布版本。训练也可把这条命令放在 `gpuctl run ... --` 后。HTTP(S)代理端点必须能从作业访问，不应填写宿主的回环地址。本工具不安装VPN、不自动接入任何第三方代理、不把宿主代理或认证秘密继承给任务。

需要认证的代理可由用户在该会话设置代理环境变量，再执行 `check` 或下载工具；不要把秘密写进代码、上传材料、公开命令示例或发布包。代理URL放在命令行可能被同机可信管理员看见，含凭据时优先交互设置环境。`check`不会输出URL查询参数、认证头、代理密码或响应正文，分享结果前仍应检查目标域名/IP是否私有。

## 出错怎么判断

- DNS失败且HTTP也失败：检查作业内解析器、上游DNS、网络连接；并不是提高GPU额度能解决的。
- DNS失败但经代理HTTP可达：代理可代解析；本地DNS问题仍存在，不应当作全网正常。
- HTTP直连失败、显式代理成功：为该进程显式配置可达代理，不要把宿主 `localhost` 代理盲目复制进沙箱。
- TLS证书失败：检查目标证书、系统时间、可信CA；不使用 `-k` 或禁用TLS检查作“修复”。
- 仅包安装失败：保留包管理器原错误，区别认证、版本/架构、依赖和网络。可把wheel或模型放入项目离线材料后发布，见项目手册。

这些是诊断入口，不是所有网络故障已经修好的保证。没有具体失败目标与作业证据时，不更改全局DNS、代理、路由或用户的训练环境。
