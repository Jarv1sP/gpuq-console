# 0.4.1 — 可恢复的数据缓存与受控直传

本页说明代码版本能力；是否已经部署、启用及验收，以管理员的实际节点回执为准。

## 数据与存储

- 数据原件与训练缓存分开管理。未分类的已有数据默认受保护，不按年龄删除。
- 只有核验了固定版本原件、授权和恢复通道的副本，才可标为可回收缓存。原件通过持续保留标记保护；其撤销需要先核对依赖副本，普通清缓存命令不能解除。
- 空间压力下按最近使用顺序选择缓存；运行、排队和新版节点传输持有的租约，以及管理员固定保留的版本，不参与清理。项目、环境和训练输出不在清理范围。
- 缓存再次使用时从固定原件恢复，完成内容校验后才成为 READY，不回退到已经变化的旧来源。
- `gpuctl data storage status/plan/pin/unpin` 提供管理员查看和保留操作。计划只读；自动回收需要单独配置和启用，安装或升级不会自动打开。

## 传输

- 新版节点复制保护源数据，目标确认停止读取后才释放源租约；丢失回执时保守保留，控制面重启不会重复启动复制。
- CLI 支持受限节点直传；大目录使用 VPS 中转需要明确选择，不因直传失败静默中转。该入口须另行部署和验收。
- 完善数据页面的来源选择、传输提示和排版，并修复 Python 3.10 下直传状态查询的空参数兼容问题。

## 已知边界

- 旧无租约的 `sync data` / 下载不读取启用了回收的缓存版本；请从受保护原件下载或使用新版节点间复制。默认关闭回收的现有部署不受此限制。
- 外部 NFS、管理员 rsync 等读取不受平台租约控制，相关源必须保持受保护，不能自行标为可回收。
- 当前提供恢复原件和缓存管理，不等于已经有独立备份、自动结果归档或云盘生产接入。
- 不自动迁移活动数据目录、不重分区、不删除旧项目，不改变用户训练里的 `/data2/数据集` 路径。
