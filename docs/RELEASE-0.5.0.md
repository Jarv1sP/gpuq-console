# 0.5.0 — 个人容器与后端稳定性

本版保留现有账号、机器授权、个人工作区和任务历史。功能是否可用仍由节点能力与管理员配置决定；升级源码不会自动开放容器、云盘或校园入口。

## 主要变化

- **个人容器**：新项目可选择 rootless OCI 环境，在容器内安装系统软件；关闭后保留个人环境，发布固定代码与镜像版本。开发终端没有 GPU，训练只获得调度分配的设备，容器内 root 不等于宿主机 root。现有 shared/isolated 项目继续使用，无须迁移。
- **终端交互**：经过验收的节点可复用有界持久 SSH 通道，减少每次输入的初始化开销；保留独立会话、单写入者和显式接管。输入结果不明时不重放。当前同一个 OCI 项目只有一个活动开发容器，不支持多个并行开发终端共写该容器。
- **运行恢复**：处理终端退出后容器引擎保留过期运行状态的情况；按精确身份收敛，不删除个人可写层。修复调度器固定 Ray 环境变量的兼容性，GPU、CPU、内存和 PID 预算仍由调度链路控制。
- **数据入口**：提供受限 HTTPS 校园直传、短期票据、续传确认、CORS/私有网络预检，以及节点个人文件的云端副本接口。已有 VPS 中转仍明确标识，大文件中转要求确认，不会暗称全部上传已绕过 VPS。
- **账号与运维**：可选的容器授权同步沿用现有有效机器权限；停用账号和撤权影响新的容器准入，不强停运行任务。旧工作区不等待这项同步。此功能默认关闭，与个人磁盘硬配额相互独立。

## 部署要求

先备份并按固定清单更新门户、执行桥及目标节点，保留当前界面、数据库、授权和运行训练。持久终端开关见 [终端会话](TERMINAL_SESSIONS.md)，容器依赖和固定镜像/CDI 配置见 [部署手册](DEPLOYMENT.md)，自动授权见 [容器成员同步](AUTOMATIC_OCI_COHORT.md)。不要用新整包覆盖节点上未经核对的兼容修补。

逐节点完成安装、开发、关闭重开、固定发布、真实 GPU 运算及资源释放后再开放；其他机型的通过记录不能替代本机验收。未启用磁盘硬配额时，容器仍可能消耗共享卷空间，必须明确这一剩余限制。

## 已验证与尚未完成

真实单卡容器工作流、八卡 Ray 预算、连续终端输入及普通成员小文件直传/云副本的范围见 [后端验收](BACKEND_ACCEPTANCE.md)。这些是不同范围的测试，不等于所有功能已对所有节点与用户开放。

电脑直接上传云盘再由节点拉取的完整流程尚未完成；现有云端副本只处理节点已有的文件。校园入口仅对已配置来源开放，网页仍需接入并核验票据上传路径。无长期满载、几十 GB 云吞吐或全部环境自动迁移的承诺。
